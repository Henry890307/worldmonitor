# Claude 精通路線圖

> 從新手到進階使用者的完整學習與應用系統
> 目標：建立穩定、可複製、可自動化的 Claude 工作流程

---

## 一、Claude 使用策略總覽

Claude 是一台**語言推理引擎**，不是搜尋引擎，也不是答案機。
要把 Claude 用好，核心策略只有四件事：

1. **給足上下文**：你給的背景越完整，Claude 越能像真正懂你領域的顧問。
2. **明確角色與任務**：角色決定語氣、任務決定產出、限制決定品質。
3. **流程化、模板化、可複製**：把每個高頻情境變成可重複呼叫的「提示模板」。
4. **從手動到自動**：先在對話中跑順，再用 Claude Code、MCP、API、Zapier 把它變成自動化工作流。

**一句話原則**：先把人腦的工作流程整理清楚，Claude 才能放大它，而不是替代它。

## 二、10 階段學習路線表

| 階段 | 學習重點 | 要會的能力 | 實作任務 | 完成標準 |
|---|---|---|---|---|
| 1. 基礎 | Claude 模型差異、上下文視窗、輸出格式、設定管理 | 知道 Opus / Sonnet / Haiku 適用情境，了解 200K~1M token 視窗、Project 設定 | 為你的工作建立一個「我的 Claude 設定卡」，包含預設模型、角色、語氣 | 能在 3 秒內判斷該用哪個模型，並穩定產出符合語氣的回答 |
| 2. 提示工程 | 角色、上下文、約束、模板、輸出格式、任務拆解 | 寫出 6 段式提示（角色／情境／任務／限制／格式／檢查） | 把目前最常用的 5 個任務改寫成模板 | 同一個模板能讓不同主題都產出穩定品質 |
| 3. 工作流程 | 從「需求」到「交付」的固定流程 | 構想→研究→大綱→初稿→優化→格式化→交付 | 用這個流程完成 1 份設計提案 + 1 篇 IG 貼文 | 流程可重複，產出品質一致 |
| 4. 技能 | 建立可重複呼叫的技能模組 | 寫作、研究、企劃、策略、簡報、程式、翻譯、摘要 | 為每個技能寫 1 份「呼叫卡」（用法 + 範例 + 限制） | 你打開卡片即可使用，不用重想提示 |
| 5. 協作 | 讓 Claude 扮演團隊角色 | 顧問、策略師、編輯、研究員、PM、審閱者 | 模擬一場「提案會議」，由 4 個角色給回饋 | 同一份提案，能讓 4 個角色給出不同層次的修改建議 |
| 6. 連接器 | 整合 Google Drive、GitHub、Notion、Slack、檔案、搜尋、API | 上傳檔案分析、跨平台同步、即時查資料 | 把一份 Google Doc 規格交給 Claude 改成簡報大綱 | 不再手動複製貼上，Claude 能直接讀取你的資料來源 |
| 7. 自動化 | MCP、AI 代理、Zapier、Make、API、守護者規則 | 寫出 1 個自動觸發的 Claude 工作流 | 例：表單 → Claude 生報價 → Email 寄出 | 整個流程不需要你介入手動操作 |
| 8. Claude 程式碼 | 用 Claude Code 做需求分析、生成、除錯、重構、測試 | 在 IDE/CLI 用 Claude Code，能跑通一個小專案 | 用 Claude Code 改一個你現有專案的功能 | 從 issue → PR → 測試全程都能用 Claude Code 跑完 |
| 9. 使用案例 | 建立你自己的「案例庫」 | 建築、室內、報價、合約、社群、行政、教會 | 為每個案例存 1 份範例 + 1 份提示模板 | 你能 5 分鐘內找到對應提示，產出 80 分草稿 |
| 10. 進階使用者 | 個人 Claude 系統 | 提示庫、模板庫、技能庫、自動化、品質檢查、版本管理 | 在 Notion 建立「我的 Claude 系統」首頁 | 任何新任務，都能對應到既有模組，不再從零開始 |

## 三、我的專屬 Claude 工作流程

> 一個流程，七個步驟，全部可由 Claude 協助

```
構想 → 研究 → 大綱 → 初稿 → 優化 → 格式化 → 發佈/交付
```

### 1. 構想（10 分鐘）
- 你做：用一段話寫下「我想做什麼、給誰、為什麼」
- Claude 做：幫你把模糊的構想擴充成 3~5 個方向，並列出每個方向的優缺點
- 提示開頭：「我有一個構想是 ___，請你幫我擴充成 3 個方向…」

### 2. 研究（15 分鐘）
- 你做：提供現有資料、案例、客戶背景
- Claude 做：摘要重點、列出競品/類案、找出資訊缺口
- 提示開頭：「以下是我蒐集的資料，請整理出 5 個重點和 3 個缺口…」

### 3. 大綱（10 分鐘）
- 你做：選定一個方向
- Claude 做：產出結構化大綱（章節、重點、字數預估）
- 提示開頭：「依據以下方向，幫我寫一份 H1/H2/H3 的大綱…」

### 4. 初稿（20 分鐘）
- 你做：審視大綱、補充細節
- Claude 做：依大綱逐段撰寫，每段先寫 70 分
- 提示開頭：「依照這份大綱，第一段請寫 200 字，語氣 ___…」

### 5. 優化（15 分鐘）
- 你做：標出不喜歡的段落
- Claude 做：改寫、強化說服力、調整語氣、增加例子
- 提示開頭：「以下段落請以更專業/口語的語氣改寫…」

### 6. 格式化（10 分鐘）
- 你做：決定最終輸出格式（簡報、PDF、IG 貼文、Notion）
- Claude 做：套版、加入 emoji/標題/列點、調整字數
- 提示開頭：「請把以上內容轉成 IG 貼文，3 張圖、每張 80 字…」

### 7. 發佈/交付（5 分鐘）
- 你做：人工審核 + 發佈
- Claude 做：產出檢查清單（錯字、語氣一致、CTA、聯絡資訊）
- 提示開頭：「請依以下清單檢查最終稿…」

## 四、完美提示公式

```
角色：你是一位 ___ 領域的 ___，擁有 ___ 年經驗，最擅長 ___。
情境：我目前正在做 ___，對象是 ___，背景條件是 ___。
任務：請你幫我 ___。
限制：必須符合 ___，不能 ___，字數約 ___，語氣 ___。
格式：請以 ___ 格式輸出（標題／列點／表格／JSON…）。
品質標準：好的版本應該滿足 ___、___、___ 三項條件。
檢查方式：完成後請你先自我檢查一次，列出 3 點可以再優化的地方。
```

### 範例填法
- 角色：你是一位資深的住宅室內設計師，擁有 15 年經驗，最擅長北歐風與小坪數規劃。
- 情境：我目前在做一份 18 坪老屋翻新提案，客戶是新婚夫妻、預算 200 萬。
- 任務：請你幫我寫一份提案的「設計理念」段落。
- 限制：必須提及採光、收納、預算控制，不能用「打造夢想之家」這種俗套句。字數 250 字內，語氣專業且溫暖。
- 格式：純文字段落，分 3 小段，每段一個核心訴求。
- 品質標準：(1) 客戶讀完能感受到「被理解」(2) 至少 1 個具體設計手法 (3) 結尾自然帶到下一段預算說明。
- 檢查方式：完成後請列出 3 點可以再優化的地方，並提出 1 個更大膽的替代版本。

## 五、10 組高品質提示詞

### 1. 建築設計提案

```
角色：你是一位擁有 20 年實務經驗的建築師，擅長將業主需求轉譯為設計語言。
情境：我正在為一位業主撰寫透天住宅新建工程的設計提案，基地 35 坪，三代同堂。
任務：產出一份「設計理念 + 空間策略 + 量體配置 + 永續設計」四段式提案。
限制：避免空泛形容詞，每段都要包含 1 個具體設計手法。
格式：分四個 H2 標題，每段 200~300 字。
品質標準：業主能讀懂、能感受、能說服家人。
檢查方式：完成後請列出 3 個業主可能會問的疑問。
```

### 2. 室內設計報價

```
角色：你是一位資深室內設計公司報價師。
情境：以下是業主需求清單與坪數，我要產出一份正式估價單。
任務：依照「設計費 / 拆除 / 泥作 / 水電 / 木作 / 系統櫃 / 油漆 / 軟裝 / 雜項 / 管理費」十大項拆解。
限制：每項都要含「單位、數量、單價、小計、備註」，並在最後加註「不包含項目」。
格式：Markdown 表格。
品質標準：清楚、可比價、無漏項。
檢查方式：完成後列出 3 個容易與業主產生爭議的細項並標註。
```

### 3. 工程估價

```
角色：你是工務經理，負責協助設計師複核估價合理性。
情境：我已產出一份估價單，需要你檢查是否合理、有無漏項、單價是否偏離市場行情。
任務：逐項評估，標出「偏高 / 偏低 / 合理」三種狀態並說明原因。
限制：以台灣 2025 年市場行情為基準，若無法判斷請註明「需現場確認」。
格式：表格 + 末段建議調整總覽。
品質標準：能幫助我下次報價更精準。
檢查方式：列出 3 個最可能踩雷的項目。
```

### 4. 合約條款

```
角色：你是熟悉營建與室內裝修法規的合約顧問。
情境：我要與業主簽訂室內裝修工程合約，金額約 250 萬，工期 90 天。
任務：草擬一份合約，包含「工程範圍、付款條件、工期、變更追加、保固、違約、爭議處理」7 大條。
限制：用語清楚、保護設計方但不失公平，符合台灣法規常見實務。
格式：標準條款式，條號清楚。
品質標準：業主看得懂，律師看得過。
檢查方式：最後列出 3 個建議我與業主口頭確認的重點。
```

### 5. IG 貼文

```
角色：你是經營室內設計品牌的社群編輯，風格溫暖、有設計感。
情境：我剛完成一個 25 坪小宅改造案，主打「收納 + 採光」。
任務：產出 1 篇 IG 貼文（圖片配文）+ 5 則 Hashtag。
限制：文案 150 字內、開頭 1 句要有畫面感、結尾 1 句 CTA。
格式：文案 + Hashtag 兩段。
品質標準：能讓潛在客戶想私訊詢問。
檢查方式：另外給 2 個替代開頭句。
```

### 6. Reels 腳本

```
角色：你是擅長設計類短影音的編劇。
情境：我要拍一支 30 秒的 Reels，主題「老屋翻新前後對比」。
任務：寫一份分鏡腳本，包含「時間軸、畫面、旁白、字卡、配樂建議」。
限制：開頭 3 秒一定要有 Hook，結尾要 CTA「私訊詢問」。
格式：表格（時間 / 畫面 / 旁白 / 字卡 / 配樂）。
品質標準：滑到 3 秒不會劃走、看完想留言。
檢查方式：另外提供 1 個更大膽的版本。
```

### 7. 教會公告

```
角色：你是教會行政同工，文字溫暖、清楚、不過度宗教化。
情境：本週日有特別聚會，包含敬拜、講道、愛宴、洗禮。
任務：寫一份 LINE 群組公告 + 一份簡短講台公告。
限制：LINE 公告 150 字內、講台公告 30 秒可念完。
格式：兩段，標題清楚。
品質標準：弟兄姊妹一看就知道時間、地點、要帶什麼。
檢查方式：列出 3 個容易被忽略的細節（例如：是否需報名、停車、兒童主日學）。
```

### 8. 活動流程

```
角色：你是專案經理，擅長活動流程設計與風險控管。
情境：我要辦一場 80 人的教會家庭日，場地室內外皆有，時間 4 小時。
任務：產出完整流程表，含「時間、地點、負責人、物資、備案」。
限制：每個時段不超過 30 分鐘、需含 1 次轉場緩衝、含雨天備案。
格式：Markdown 表格。
品質標準：當天可直接列印當作工作手冊。
檢查方式：列出 5 個最容易出包的風險點。
```

### 9. 會議整理

```
角色：你是專業會議記錄員。
情境：以下是我這場會議的逐字稿/筆記。
任務：整理成「決議事項 / 待辦事項 / 議題討論 / 下次會議重點」四段。
限制：待辦事項必須含「負責人、期限、產出物」三欄。
格式：四個 H2 + 表格。
品質標準：沒參加會議的人，看完也知道發生什麼事。
檢查方式：標註 3 處你覺得「資訊不足、需追問」的地方。
```

### 10. AI 自動化規劃

```
角色：你是 AI 自動化顧問，熟悉 Claude / MCP / Zapier / Make。
情境：我是一人設計工作室，每天花 2 小時在報價、回 LINE、整理會議記錄。
任務：幫我設計 3 個可落地的自動化流程。
限制：每個流程都要寫清楚「觸發、Claude 動作、輸出、串接工具」，且我能 1 週內自己架完。
格式：三個區塊，每個區塊 5 個欄位。
品質標準：1 週後我每天至少省 1 小時。
檢查方式：列出每個流程的 1 個失敗風險與對應方案。
```

## 六、Claude 團隊角色設定

> 把 Claude 當成一個 8 人虛擬團隊，每個角色都有自己的提示卡

### 1. 建築顧問

```
你是一位資深建築師（25 年實務經驗），熟悉台灣建築法規與在地工法。
回答時請：
1. 先釐清基地條件、業主需求、預算
2. 提出 2~3 個設計策略並比較
3. 指出法規風險與必要送審項目
4. 用業主聽得懂的語言說明
回覆風格：理性、務實、不浮誇。
```

### 2. 室內設計顧問

```
你是擅長住宅與商空的室內設計師，特別重視「動線、收納、採光、預算控制」。
回答時請：
1. 先問清楚使用人數、生活習慣、預算上限
2. 提供至少 1 個主案 + 1 個備案
3. 對每個建議都註明「預算影響」與「工期影響」
回覆風格：溫暖、有畫面、能落地。
```

### 3. 工程估價員

```
你是負責複核估價單的工務經理。
任務：檢查項目是否齊全、單價是否合理、是否有常見漏項。
回答時請：
1. 用表格呈現「項目 / 單價 / 合理區間 / 評估」
2. 標出高風險項
3. 提出 3 個與業主溝通的建議
回覆風格：嚴謹、保守、精確。
```

### 4. 合約審查員

```
你是熟悉營建/裝修合約的法務助理。
任務：審閱合約條款，找出對我方不利或模糊的條文。
回答時請：
1. 逐條標註「中立 / 對我方有利 / 對我方不利」
2. 對不利條款提出修改建議文字
3. 提示需口頭溝通的重點
回覆風格：理性、條列、不情緒化。
```

### 5. 社群內容編輯

```
你是設計品牌的社群編輯，熟悉 IG / Threads / FB / Reels。
任務：把我提供的素材，轉成各平台適用的內容。
回答時請：
1. 依平台調整字數與語氣
2. 加上 Hook 與 CTA
3. 給出 5 個 Hashtag 與 1 個替代版本
回覆風格：年輕、溫度、有梗。
```

### 6. 行政秘書

```
你是我的私人行政秘書，協助整理會議、信件、行程、待辦。
任務：把雜亂資料整理成清單、表格、待辦事項。
回答時請：
1. 每筆待辦必須有「負責人 / 期限 / 產出物」
2. 用優先級排序（P0 / P1 / P2）
3. 提示我今天最重要的 3 件事
回覆風格：簡潔、結構化、不囉嗦。
```

### 7. 專案經理

```
你是 PMP 認證的專案經理，擅長設計與工程專案。
任務：幫我規劃專案時程、追蹤進度、找出風險。
回答時請：
1. 用 WBS 拆解工作
2. 用甘特圖思維給出時程
3. 列出 Top 3 風險與對應方案
回覆風格：理性、有節奏感、敢說壞消息。
```

### 8. AI 自動化顧問

```
你是熟悉 Claude / MCP / Zapier / Make / API 的自動化顧問。
任務：協助我設計可落地的自動化工作流。
回答時請：
1. 先確認我的現況痛點與工具
2. 設計可 1 週內上線的 MVP 流程
3. 標註成本、學習曲線、維運難度
回覆風格：實作導向、避免過度工程化。
```

## 七、自動化流程設計

> 5 個可立即落地的 Claude 自動化流程

### 流程 1：報價自動產生器

| 項目 | 內容 |
|---|---|
| 用途 | 客戶填表 → 自動產生估價單草稿 |
| 輸入資料 | Google Form（坪數、屋況、需求、預算） |
| Claude 動作 | 依需求套用報價模板、自動加總、產出 Markdown 表格 |
| 輸出結果 | 一份 PDF 估價單 + 一封寄給客戶的 Email 草稿 |
| 串接工具 | Google Forms → Zapier/Make → Claude API → Google Docs → Gmail |

### 流程 2：每週社群內容工廠

| 項目 | 內容 |
|---|---|
| 用途 | 每週自動產出 3 篇 IG 貼文 + 1 支 Reels 腳本 |
| 輸入資料 | 本週案例照片資料夾 + 案例摘要表 |

## 八、常見錯誤與修正方式

| # | 常見錯誤 | 為什麼錯 | 修正版提示 |
|---|---|---|---|
| 1 | 提示太模糊（「幫我寫個提案」） | Claude 不知道對誰、目的、長度 | 「請以資深建築師角色，為 35 坪透天住宅業主撰寫 500 字設計理念，需含採光、收納、永續三項。」 |
| 2 | 沒有指定格式 | 產出格式不一致，難複製貼上 | 「請以 Markdown 表格輸出，欄位：項目 / 單價 / 小計 / 備註。」 |
| 3 | 一次要求太多 | 注意力分散、品質下降 | 拆成「步驟 1：先給我大綱」「步驟 2：根據大綱寫第一段」分批要 |
| 4 | 沒有提供背景資料 | 產出空泛、套話多 | 「以下是業主資料與基地條件 [貼上資料]，請依此撰寫…」 |
| 5 | 沒有品質檢查 | 第一稿就交付，常有漏洞 | 「寫完後請自我檢查 3 點可優化處，並列出 3 個業主可能的反駁。」 |
| 6 | 一直重開新對話 | 失去脈絡、模板重做 | 用 Projects 把長期專案放進去，讓 Claude 永遠看得到背景 |
| 7 | 拿 Claude 當搜尋引擎 | 它不擅長即時資訊 | 用「連接器 / 網路搜尋」工具，或自己貼資料給它分析 |
| 8 | 不指定語氣 | 產出忽冷忽熱、不像你 | 「語氣：專業但溫暖，避免過度行銷詞。範例句：___」 |
| 9 | 忽略限制條件 | 預算/字數/時間沒講，產出不可用 | 「字數 300 內、預算上限 200 萬、工期 60 天。」 |
| 10 | 不存提示 | 每次都重寫，浪費時間 | 建立「個人提示庫」（Notion 或本文件第五節） |

## 十、可直接儲存成 Notion 或 Markdown 的版本

> 本檔案本身即為 Markdown 版本，可直接複製貼到 Notion / Obsidian / VSCode。
> 路徑：`docs/claude-mastery-roadmap.md`

### 如何使用本文件

1. **首次設定**：複製本文件到你的 Notion，建立一個 Database 叫「Claude 系統」。
2. **拆分為頁面**：把第 5、6、7 節各自拆成 Notion 的子頁面，方便快速搜尋。
3. **每週更新**：每完成一個提示模板，就回到第 5 節新增。
4. **每月複盤**：依第 9 節的「複盤日」回顧進度。
5. **版本管理**：用 Git 或 Notion 的版本歷史追蹤每次修改。

